### 2.2 類別功能

| 功能 | 說明 |
|------|------|
| **開課權限** | 課程管理者只能在被指派的類別下建課程 |
| **權限繼承** | 院區管理員可管理院區類別及所有子類別 |
| **可擴充性** | 院區管理員可在 15 子類別下新增子子類別 |

### 2.3 類別權限規則

| 角色 | 可做的事 | 不可做的事 |
|------|----------|------------|
| 系統管理員 | 管理所有類別 | - |
| 院區管理員 | 管理本院區類別、指派課程管理者 | 指派院區管理員 |
| 課程管理者 | 在指派類別下開課 | 管理類別、指派他人 |

## 三、屬性系統

### 3.1 屬性分類

```
屬性
├── 地點屬性（Location）
│   ├── 院區（10 個，固定）：嘉基、大林慈濟、台北慈濟...
│   └── 部門（15 個，固定）：護理部、藥劑科、中醫科...
│
└── 角色屬性（Role）
    ├── 共用角色（系統管理員建立）：醫師、護理師...
    └── 院區專屬角色（院區管理員建立）：新進員工、實習生...
```

### 3.2 屬性資料庫結構

```sql
-- 屬性類型
attribute_types
├── id
├── code        -- 'hospital', 'department', 'role'
├── name        -- '院區', '部門', '角色'
├── scope       -- 'global', 'hospital'
└── is_multi_select  -- true/false

-- 屬性值
attribute_values
├── id
├── type_id     -- FK → attribute_types
├── hospital_id -- NULL=共用, 有值=院區專屬
├── code        -- 統一代碼（跨院區匹配用）
├── name        -- 顯示名稱（各院區可自訂）
└── is_active

-- 使用者屬性（多對多）
user_attributes
├── user_id
├── attribute_value_id
└── created_at
```

### 3.3 屬性範例資料

| id | type | hospital_id | code | name |
|----|------|-------------|------|------|
| 1 | 院區 | NULL | dalin | 大林慈濟 |
| 2 | 院區 | NULL | taipei | 台北慈濟 |
| 3 | 部門 | NULL | nursing | 護理部 |
| 4 | 角色 | NULL | doctor | 醫師 |
| 5 | 角色 | 1 (大林) | new_emp | 新進員工 |
| 6 | 角色 | 2 (台北) | new_emp | 新人 |

### 3.4 屬性匹配規則

```
跨院區匹配：使用 code
├── code='new_emp' → 匹配大林的「新進員工」和台北的「新人」

院區內匹配：使用 id
├── attribute_value_id=5 → 只匹配大林的「新進員工」
```

### 3.5 使用者多屬性範例

```
王小明的屬性：
├── 院區：大林慈濟
├── 部門：護理部
├── 角色：護理師
├── 角色：新進員工
└── 角色：感控委員
```

## 四、課程報名規則

### 4.1 課程管理者的權限範圍

```
課程管理者權限由其所屬類別決定：

大林慈濟 > 護理部 的課程管理者
├── 可自動/手動加入：院區=大林慈濟 且 部門=護理部 的學員
├── 可開放自選：任何人（根據設定）
└── 不可手動加入：其他院區或部門的學員
```

### 4.2 類別與屬性對應

```sql
-- 類別→屬性對應表
category_attribute_mapping
├── moodle_category_id  -- Moodle 類別 ID
├── hospital_attr_id    -- 對應的院區屬性 ID
└── department_attr_id  -- 對應的部門屬性 ID（可為 NULL）
```

## 五、課程包（學習路徑）

### 5.1 課程包概念

```
課程包 = 一組相關課程 + 目標對象 + 完成要求

範例：
├── 名稱：新進人員訓練
├── 目標：角色=新進員工（code 匹配）
├── 課程：5 門課（有順序）
├── 必修：前 4 門必修，第 5 門選修
└── 完成條件：必修全部完成
```

### 5.2 課程包資料庫結構

```sql
-- 課程包
learning_paths
├── id
├── hospital_id     -- NULL=全院共用, 有值=院區專屬
├── name
├── description
├── target_rule     -- JSON: 目標屬性條件
├── is_required     -- 是否必修
├── created_by      -- 建立者 user_id
└── is_active

-- 課程包內的課程
learning_path_courses
├── path_id
├── moodle_course_id
├── display_order
├── is_required     -- 此課程是否必修
└── created_at

-- 課程包負責人（可加入課程的人）
learning_path_managers
├── path_id
└── user_id
```

### 5.3 課程包建立流程

```
1. 院區管理員建立課程包
   ├── 設定名稱：新進人員訓練
   ├── 設定目標：角色=新進員工
   ├── 指派負責人：可以往此課程包加課程的教師
   └── 設定是否必修

2. 課程管理者開課後
   ├── 回到 Portal
   ├── 選擇「加入課程包」
   └── 勾選「新進人員訓練」

3. 學員登入
   ├── 系統檢查學員屬性
   ├── 匹配到「新進員工」
   ├── 顯示「新進人員訓練」課程包
   └── 顯示完成進度
```
